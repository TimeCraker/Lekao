## 2. 端到端数据流

### 2.1 用户提交灵感

```
用户点击 "+ 提个建议"
  ↓
弹窗表单（title 必填 ≤ 50 字 / description 必填 ≤ 500 字）
  ↓ POST /api/lekao/ideas
API 校验（顺序固定）：
  - banned 拦截（proxy.ts 已兜底，但 API 内再校验一次防绕过）
  - 敏感词过滤（title + description 命中 → 422）
  - 每日 1 次：SELECT COUNT(*) WHERE user_id=? AND created_at >= today UTC+8
  - 重复标题检测：SELECT COUNT(*) WHERE user_id=? AND title=? AND created_at >= today
  - title/description 长度校验
  ↓ INSERT INTO lekao_ideas
  ↓ 200 { id, title, ... }
UI: SuccessBurst 弹一下 + 自动刷新列表
```

### 2.2 点赞 / 取消点赞（toggle）

```
用户点击 👍 按钮
  ↓ POST /api/lekao/ideas/[id]/like
API 校验：登录态 + idea 存在
  ↓ 查 lekao_idea_likes WHERE idea_id=? AND user_id=?
  - 存在 → DELETE（取消）
  - 不存在 → INSERT（点赞）
  ↓ 返回新状态 { liked: true/false, count: N }
UI: 按钮按下 spring 缩放 + 数字平滑更新
```

### 2.3 评论（每用户对每个灵感 1 条 + 删除 = 永久禁）

```
用户点击灵感卡片的 "💬 评论" 按钮 → 展开评论区
  ↓
评论区显示已发布的评论列表（按时间正序）+ 评论输入框
  ↓ POST /api/lekao/ideas/[id]/comments
API 校验：
  - banned 拦截
  - 敏感词过滤（content 命中 → 422）
  - 唯一活跃评论检测：SELECT COUNT(*) WHERE idea_id=? AND user_id=? AND status='visible'
    - 含 1 条 → 拒绝 "你已经评论过了"
    - 含 status='banned' 历史 → 拒绝 "评论已撤回，无法再次评论"
  - content 长度 ≤ 200 字
  ↓ INSERT INTO lekao_idea_comments (status='visible')
  ↓ 200 { id, content, userEmail, createdAt }
UI: 评论输入框清空 + 列表自动刷新 + 新评论标"刚刚"
```

**评论删除（软删除 = 永久禁评）**：

- 用户自己删：UPDATE lekao_idea_comments SET status='banned' WHERE id=? AND user_id=? AND status='visible'
  - 不真删记录，保留历史供 audit
  - **删了之后 status='banned' 占位**，partial unique index 不允许再发（decision 10）
- admin 删：同上但不限 user_id（写审计）

**为什么是软删除不是硬删除**：

- partial unique index `WHERE status='visible'` 必须在 DB 层强制，否则用户在 API 层绕过
- 真 DELETE 记录 → unique 约束释放 → 用户可重发 → 违反"永久禁"决策
- 软删除保留行 + status='banned' → partial unique index 仍生效 → 永久禁

### 2.4 admin 标记状态 + 删灵感 + 删评论

```
admin 进入 /admin/ideas
  ↓ 列表展示所有灵感（邮箱 + 点赞数 + 评论数 + 当前状态）
admin 操作：
  - 切换状态 → PATCH /api/admin/ideas/[id]/status → 写审计
  - 删除灵感 → DELETE /api/admin/ideas/[id] → 写审计 + 级联删评论 + 点赞
  - 进入"评论管理"子页 → DELETE /api/admin/comments/[commentId] → 写审计
```

### 2.5 TOP 3 排行榜

```
页面加载时 GET /api/lekao/ideas?limit=3&sort=likes
  ↓ SQL:
    SELECT i.*, COUNT(DISTINCT l.user_id) AS like_count,
           COUNT(DISTINCT c.id) AS comment_count
    FROM lekao_ideas i
    LEFT JOIN lekao_idea_likes l ON l.idea_id = i.id
    LEFT JOIN lekao_idea_comments c ON c.idea_id = i.id AND c.status = 'visible'
    GROUP BY i.id
    ORDER BY like_count DESC, i.created_at DESC
    LIMIT 3
UI: 顶部横排 3 张卡（🏆🥈🥉 emoji + 标题 + 点赞数 + 评论数）
```

### 2.6 列表筛选 + 搜索 + 排序

```
用户操作：
  - Tab 切换：全部 / 我提的 / 我赞过的
  - 搜索框：title/description 模糊匹配（`ILIKE '%q%'`）
  - 排序切换：热度（点赞倒序）/ 最新（时间倒序）
  ↓ GET /api/lekao/ideas?tab=mine&q=xxx&sort=latest&limit=50
API 参数校验 + SQL 拼接
```

## 5. 数据结构

### 5.1 Prisma Schema 增量（3 张新表）

```prisma
// prisma/schema.prisma 末尾追加

model LekaoIdea {
  id          String    @id @default(uuid()) @db.Uuid
  userId      String    @map("user_id")
  userEmail   String    @map("user_email")        // 冗余存，避免每次 join users
  title       String    @db.VarChar(50)
  description String    @db.VarChar(500)
  status      String    @default("open") @db.VarChar(20)  // 'open' | 'planned' | 'done'
  createdAt   DateTime  @default(now()) @map("created_at") @db.Timestamptz
  updatedAt   DateTime  @updatedAt @map("updated_at") @db.Timestamptz
  likes       LekaoIdeaLike[]
  comments    LekaoIdeaComment[]

  @@index([userId])
  @@index([createdAt(sort: Desc)])
  @@index([status])
  @@map("lekao_ideas")
}

model LekaoIdeaLike {
  ideaId    String   @map("idea_id") @db.Uuid
  userId    String   @map("user_id")
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz
  idea      LekaoIdea @relation(fields: [ideaId], references: [id], onDelete: Cascade)

  @@id([ideaId, userId])           // 联合主键天然防重复
  @@index([userId])
  @@map("lekao_idea_likes")
}

model LekaoIdeaComment {
  id          String    @id @default(uuid()) @db.Uuid
  ideaId      String    @map("idea_id") @db.Uuid
  userId      String    @map("user_id")
  userEmail   String    @map("user_email")
  content     String    @db.VarChar(200)
  status      String    @default("visible") @db.VarChar(20)  // 'visible' | 'hidden' | 'banned'
  createdAt   DateTime  @default(now()) @map("created_at") @db.Timestamptz
  idea        LekaoIdea @relation(fields: [ideaId], references: [id], onDelete: Cascade)

  // 不再用 @@unique — 改用 partial unique index (migration 里手写) 配合 status='banned' 软删除
  @@index([ideaId, userId])        // API 查询用
  @@index([ideaId, createdAt])
  @@index([status])
  @@map("lekao_idea_comments")
}
```

### 5.2 手写 Migration SQL

```sql
-- prisma/migrations/20260625000000_inspiration_wall/migration.sql

-- 1. 灵感墙主表
CREATE TABLE IF NOT EXISTS "lekao_ideas" (
  "id"          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "user_id"     TEXT NOT NULL,
  "user_email"  TEXT NOT NULL,
  "title"       VARCHAR(50) NOT NULL,
  "description" VARCHAR(500) NOT NULL,
  "status"      VARCHAR(20) NOT NULL DEFAULT 'open',
  "created_at"  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  "updated_at"  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS "idx_lekao_ideas_user_id" ON "lekao_ideas" ("user_id");
CREATE INDEX IF NOT EXISTS "idx_lekao_ideas_created_at" ON "lekao_ideas" ("created_at" DESC);
CREATE INDEX IF NOT EXISTS "idx_lekao_ideas_status" ON "lekao_ideas" ("status");

-- 2. 点赞表（联合主键防重复）
CREATE TABLE IF NOT EXISTS "lekao_idea_likes" (
  "idea_id"    UUID NOT NULL REFERENCES "lekao_ideas"("id") ON DELETE CASCADE,
  "user_id"    TEXT NOT NULL,
  "created_at" TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY ("idea_id", "user_id")
);

CREATE INDEX IF NOT EXISTS "idx_lekao_idea_likes_user_id" ON "lekao_idea_likes" ("user_id");

-- 3. 评论表（partial unique index 配合软删除实现"删了永久禁"）
CREATE TABLE IF NOT EXISTS "lekao_idea_comments" (
  "id"          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "idea_id"     UUID NOT NULL REFERENCES "lekao_ideas"("id") ON DELETE CASCADE,
  "user_id"     TEXT NOT NULL,
  "user_email"  TEXT NOT NULL,
  "content"     VARCHAR(200) NOT NULL,
  "status"      VARCHAR(20) NOT NULL DEFAULT 'visible',
  "created_at"  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ⭐ partial unique index：只对 status='visible' 强制唯一
-- 删除评论 = UPDATE status='banned'（行保留），index 仍生效 → 永久禁
CREATE UNIQUE INDEX IF NOT EXISTS "uniq_lekao_idea_comments_active"
  ON "lekao_idea_comments" ("idea_id", "user_id")
  WHERE "status" = 'visible';

CREATE INDEX IF NOT EXISTS "idx_lekao_idea_comments_idea_user"
  ON "lekao_idea_comments" ("idea_id", "user_id");
CREATE INDEX IF NOT EXISTS "idx_lekao_idea_comments_idea_created"
  ON "lekao_idea_comments" ("idea_id", "created_at");
CREATE INDEX IF NOT EXISTS "idx_lekao_idea_comments_status"
  ON "lekao_idea_comments" ("status");
```

### 5.3 字段冗余设计说明

- `user_email` 在 3 张表都冗余存（想法 + 点赞虽只需 user_id，但评论里要展示邮箱 → 直接读；admin 列表展示邮箱 → 直接读）
- **不加 FK 引用 users**（共享表只读铁律，与 lekao_coin_log / lekao_audit_log 一致）
- `status` 字段在评论表预留（v2.2.0 只用 `visible`，`hidden` 留给 P2 admin 隐藏评论用）

## 7. 敏感词过滤

### 7.1 词表设计

**位置**：`src/lib/sensitive-words.ts`

**覆盖范围**（基础 30-50 个词）：

- 政治敏感（10 个常见）
- 色情（8 个常见）
- 暴力 / 恐怖（5 个常见）
- 严重侮辱（8 个常见）
- 广告引流关键词（5 个常见："加微"、"私聊"等）

**维护**：纯前端数组常量，后续可单独 commit 增删

### 7.2 工具函数

```typescript
// src/lib/sensitive-words.ts
const SENSITIVE_WORDS = [
  // ... 约 30-50 个基础词
];

/**
 * 检查文本是否含敏感词（大小写不敏感、忽略空格）
 */
export function containsSensitiveWords(text: string): boolean {
  const normalized = text.toLowerCase().replace(/\s+/g, "");
  return SENSITIVE_WORDS.some((w) => normalized.includes(w.toLowerCase()));
}

/**
 * 找出文本中所有匹配的敏感词（用于前端实时提示）
 */
export function findSensitiveWords(text: string): string[] {
  const normalized = text.toLowerCase().replace(/\s+/g, "");
  return SENSITIVE_WORDS.filter((w) => normalized.includes(w.toLowerCase()));
}
```

### 7.3 校验时机

| 字段             | 校验时机                         | 错误响应             |
| ---------------- | -------------------------------- | -------------------- |
| 灵感 title       | 提交 API + 表单 onBlur           | 422 + "标题含敏感词" |
| 灵感 description | 提交 API + 表单 onBlur           | 422 + "描述含敏感词" |
| 评论 content     | 提交 API + 表单 onChange（可选） | 422 + "评论含敏感词" |
| 用户名           | 不做（已有 users 表）            | —                    |

### 7.4 前端实时提示（可选优化）

`IdeaSubmitDialog` 输入框 onChange 时调 `findSensitiveWords()`：

- 命中 → 输入框下方红字"含敏感词：xxx, xxx"

### 7.5 评论删除 = 永久禁该灵感评论位（决策 #10）

**DB 层强制**（API 改代码也绕不过）：

```sql
CREATE UNIQUE INDEX uniq_lekao_idea_comments_active
  ON lekao_idea_comments (idea_id, user_id)
  WHERE status = 'visible';
```

**应用层行为**：

- 删评论 → `UPDATE status='banned'`（行不删）
- 再提交评论 → 命中 partial unique index → 23505 错误 → API 返回 422 "评论已撤回，无法再次评论"
- 用户看到的状态：灵感卡片显示 "💬 你已撤回评论"（替代评论输入框）

**为什么不做 admin 改评论功能**：v2.2.0 不做（过度设计）；真要改 = 删自己的（status='banned'）+ 让 admin 重发，复杂；用户拍板"删了永久禁" = 决策清晰，admin 也尊重。

## 9. 反模式 / 陷阱

### 9.1 不能犯的错

| #   | 反模式                                       | 正确做法                                                         |
| --- | -------------------------------------------- | ---------------------------------------------------------------- |
| 1   | 用 `prisma db push --force` 加新表           | **手写 SQL migration + `migrate deploy`**                        |
| 2   | 在 `lekao_ideas.user_id` 加 FK 引用 users.id | **不加 FK**，TEXT 即可（共享表只读铁律）                         |
| 3   | 用 `revalidatePath` 全量刷新                 | 用 `useRouter().refresh()` 或本地状态更新                        |
| 4   | 点赞表用 unique 索引而非联合主键             | 用 `@@id([ideaId, userId])` 联合主键                             |
| 5   | 排行榜用 Redis 缓存                          | 直接 SQL `JOIN + GROUP BY + ORDER BY`（量 < 10k 不需要缓存）     |
| 6   | 每日 1 次用 cron 维护计数表                  | 直接 `WHERE created_at >= CURRENT_DATE` 查                       |
| 7   | 提交按钮没做 disabled 状态                   | `useState submitting` + `disabled={submitting}` + 失败保留表单值 |
| 8   | admin 状态变更不写审计日志                   | **必须写 `lekao_audit_log`**（合规铁律）                         |
| 9   | **新增**：admin 删灵感 / 删评论不写审计      | 同样必须写 `lekao_audit_log`（v2.2.0 加的合规要求）              |
| 10  | **新增**：评论做成嵌套回复                   | 全部平铺按时间正序，避免 parent_id + 缩进复杂度                  |
| 11  | **新增**：敏感词用 AI 智能识别               | 基础词表 + 422 拒绝，过度 AI 化不值                              |
| 12  | **新增**：评论无限条（防刷屏失控）           | `@@unique([ideaId, userId])` 每用户每灵感 1 条                   |
| 13  | **新增**：评论显示用户真实姓名               | 只显示 `user_email`（决策 2 一致性）                             |
| 14  | **新增**：列表分页缺失拖慢大列表             | 加 `limit=50` 上限（v2.2.0 暂不分页）                            |

### 9.2 性能陷阱

| 场景                              | 风险        | 对策                                                             |
| --------------------------------- | ----------- | ---------------------------------------------------------------- |
| 点赞 toggle 每次都 JOIN + COUNT   | N+1         | API 返回 `{ liked, count }`，前端缓存（useState）                |
| 列表查询 JOIN 三张表              | 慢          | 加 `idx_lekao_ideas_created_at` / `idx_lekao_idea_likes_user_id` |
| 评论展开每次重新请求              | N+1         | 一次性 GET 全部已展开评论（量小，< 100）                         |
| 搜索 SQL `ILIKE '%q%'` 全表扫     | 慢          | 数据量 < 10k 时可接受，超过再考虑全文索引                        |
| 提交按钮连点导致重复提交          | 重复 INSERT | `useState submitting` + `disabled={submitting}` + API 层再校验   |
| 敏感词 `String.includes` 频繁调用 | 不显著      | 词表长度固定，复杂度 O(N)，N < 50 无忧                           |

### 9.3 安全铁律（沿用 v2.1.0 P0 模式）

| 项                    | 模式                                                                         |
| --------------------- | ---------------------------------------------------------------------------- |
| banned 拦截           | proxy.ts + API 内 `session.user.banned === true` 检查                        |
| 每日 1 次             | API 层查 `SELECT COUNT(*) WHERE user_id=? AND created_at >= today UTC+8`     |
| 每用户每灵感 1 条评论 | `@@unique([ideaId, userId])` DB 约束                                         |
| 删除权限              | `WHERE id=? AND user_id=?` 防越权                                            |
| admin 鉴权            | API 入口 `requireAdmin()` + proxy.ts 已拦                                    |
| 审计日志              | admin 状态变更 / 删灵感 / 删评论 都写 `lekao_audit_log`（复用 v2.0.0 P0 表） |
| 长度校验              | API 层 + schema 层双校验（防 bypass）                                        |
| 限流                  | T2 提交 API 加 IP 限频（沿用 send-code 模式：60s 1 次 + 1 分钟 5 次）        |
| 敏感词过滤            | API 层必过，前端可选实时提示                                                 |

### 9.4 沿用既有组件（不重复造轮子）

## 📝 备注

- **为什么 #1 包含评论核心？** 评论提交/列表/删除 闭环 = 4 个 API + 1 个组件 = 用户主流程必须可验才能进入 #2
- **为什么不在 #2 才加 admin？** admin 状态标记是给产品团队用的，跟用户主流程解耦，独立 commit 更易 review + 回滚
- **为什么评论每用户每灵感 1 条？** 跟"灵感墙定位是收集想法"匹配；避免刷屏；想更新评论 = 删了重发
- **为什么用全员评论而不是 admin 单方面回复？** 助教之间也能互助（"我也想要""OCR 错题后能自动分类"）；增加互动；admin 也参与讨论
- **为什么 v2.2.0 不是 v2.1.2？** v2.1.0/2.1.1 都是 bug fix，纯 v2.1.x 补丁线；v2.2.0 是**新增功能**，需要 minor bump（semver）
- **为什么 P2 错题集数据备份先不动？** v2.2.0 范围清晰 = 灵感墙（含评论），不扩大 scope（CLAUDE.md "不要过度架构" 铁律）
- **敏感词词表维护**：本版本固定 30-50 词，后续如果实际触发 spam 多 → 单独 commit 增量添加，不动主流程
