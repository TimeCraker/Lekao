## 1. 项目背景与定位

### 1.1 一句话定位
让培训机构助教从"抄错题、写小结、写反馈"里解放出来，每次课省 1-2 小时。

### 1.2 解决什么问题

| 痛点 | 现状（手动） | 用 Lekao 后 |
|------|------------|-----------|
| 错题集制作 | 1 个班 30 学生 × 抄错题号 + 拍照 + 排版 = 1-2 小时 | 上传 Excel + 拖拽图片 = 5 分钟 |
| 课堂小结 | 每节课都要写，模板类似，200-500 字/份 | 上传讲义图片 + 选模板 = 一键生成 |
| 课堂反馈 | 要发给家长群，每份 200 字 + 客套话 | 讲义图片 + 简单描述 = AI 按模板生成 |

### 1.3 不做什么（本期）
- ❌ 学生管理 / 班级管理（V2）
- ❌ 多助教协作（V2）
- ❌ 微信支付 / 微信 OAuth（等公司主体注册）
- ❌ 移动端 App（V2，先做 Web 响应式）

## 2. 目标用户

### 2.1 用户画像
- **角色**：培训机构助教
- **年龄**：22-35 岁
- **学历**：本专科及以上
- **日常工作**：每天 1-3 个班，每个班 20-40 学生
- **电脑水平**：会用 Word/Excel/微信，会拍照上传
- **AI 接受度**：会用 ChatGPT 类工具，对"AI 干活"有期待

### 2.2 使用场景
- **场景 A**（主力 · 每天）：下课后立刻生成当天错题集 → 群里发给老师/家长
- **场景 B**（每天）：课后写课堂小结 → 备课组存档
- **场景 C**（每天）：课后写课堂反馈 → 家长群发

### 2.3 付费意愿
- **助教本人**：付费意愿低（工资不高，省时间但不是自己掏钱）
- **培训机构（老板）**：付费意愿高（按月/年订阅，机构买单）
- **过渡**：先做 T-Coin 单次扣费（老板/老板助理充值后发给助教用）

## 3. 三大核心业务流程

### 3.1 错题集生成（主力功能 · 免费）

**为什么免费**：纯前端集成，不消耗 AI API，对助教吸引力最大。

#### 3.1.0 MVP Excel 标准模板契合度 ⭐（冷启动基准线）

**问题**：大纲写了要兼容各种奇葩格式，但代码冷启动阶段需要一个**基准线**让助教"开箱即用"。

**MVP 官方推荐 Excel 结构**（第一列固定）：

| 列 | 列名（中文） | 列名（英文别名） | 格式示例 | 必填 |
|----|------------|---------------|---------|------|
| 1 | 学生姓名 | 姓名 / 名字 / Name | 张三 | ✅ |
| 2 | 课堂测验错题 | 堂测 / 课堂 / Quiz | T-3, T-5 | ❌ |
| 3 | 课后作业错题 | 作业 / Homework | H-1, H-2 | ❌ |
| 4 | 备注 | 备注 / Note | 缺考 / 请假 | ❌ |

**题号格式**：
- 堂测：`T-数字`（如 `T-3`）/ `T数字`（如 `T3`）/ 纯数字
- 作业：`H-数字`（如 `H-1`）/ `H数字`（如 `H1`）/ 纯数字
- 多题分隔符：中文逗号 `，` / 英文逗号 `,` / 空格 / 顿号 `、` / 换行 / 连续空格

**产品动作**：
- 前端 `/dashboard/mistake` 页面顶部提供**标准模板 .xlsx 下载按钮**
- 用户按模板导入 = 体验完美（0 模糊匹配成本）
- **其他杂乱格式的模糊匹配放 Phase 2**（不在本期范围）

#### 3.1.1 核心改进：全班错题号"去重提炼"算法 ⭐

**传统做法**：按学生逐个建题 → 30 个学生 × 平均 5 道错题 = 150 张图片要上传。

**Lekao 做法**：提取全班错题号的**并集（去重列表）** → 一个班往往集中在 6-10 道核心题上。

**举例**：
```
班级 30 人，解析 Excel 后得到的错题号：
- 张三：T-3, T-7
- 李四：T-3, T-7
- 王五：T-7, T-12
- ...

全班去重并集：{T-3, T-7, T-12}
→ 系统只需列 3 道题让助教上传图片
→ 自动分发映射到张三、李四、王五各自的 Word 文档
```

**业务价值**：30 人班级 150 张图片 → 实际只要上传 6-10 张（去重后），效率提升 15-25 倍。

#### 3.1.2 免命名智能图片映射 ⭐

**反人性设计**：要求助教把手机照片重命名为 `T-3.jpg` / `T-7.jpg` 是不现实的。

**Lekao 交互**：
- **左侧**：列出全班去重后的核心题号（带计数："T-3（18 人错）"）
- **右侧**：每个题号对应一个图片上传槽位
- **操作**：助教拍完照直接把图片拖进对应题号框，**无需命名**
- **绑定**：前端无感知地把"题号 ↔ 图片"绑死

#### 3.1.3 国内教务 Excel 编码兼容 ⭐

**痛点**：国内培训机构导出的 Excel 千奇百怪（旧版 .xls / GBK 编码 / 繁体表头 / 合并单元格）。

**Lekao 应对**：
- 解析库必须支持 GBK 字符集解码（中文姓名不能乱码）
- 支持 `.xlsx` + `.xls` 双格式
- 兼容分隔符：中文逗号 `，` / 英文逗号 `,` / 空格 / 顿号 `、` / 换行 / 连续空格
- 列名识别灵活（"姓名"/"学生姓名"/"名字"/"Name" 都认）
- 全对处理：堂测和作业两列都为空 → 只记日期 + "全对"

#### 3.1.4 前端压缩防崩溃 ⭐

**痛点**：30-40 人班级 + 上百张手机高清原图 = 前端打包瞬间吃满内存导致浏览器标签页崩溃。

**Lekao 应对**：
- 助教上传图片的瞬间，浏览器本地自动等比压缩到 500KB 左右
- 再进行 Word 组装，彻底规避前端内存溢出

#### 3.1.5 本地草稿箱防丢失 ⭐

**痛点**：纯前端集成 ≠ 数据不落盘 = 助教误刷新网页/浏览器崩溃 = 所有工作丢失。

**Lekao 应对**：
- 解析 Excel 后的数据结构 + 已匹配的图片缓存到本地
- 页面异常恢复时支持"一键还原未完成的工作"
- 缓存方案：LocalStorage（轻数据）+ IndexedDB（大图片 Blob）

#### 3.1.6 COS 前端直传 ⭐

**痛点**：助教上传的手机原图几 MB 一张，走后端中转极易耗光 3.6GB 服务器内存。

**Lekao 应对**：
- 图片直接传到对象存储（COS / OSS / S3），后端只生成"临时上传凭证"
- 应用服务器全程不接触图片大数据，**零内存压力**

#### 3.1.7 输出格式

**输入**：Excel 课堂反馈表（用户上传）
**处理**：Excel 解析 → 错题号去重 → 助教拖拽图片 → 自动绑定 → 拼装预览
**输出**：
- Word (.docx) 导出
- Markdown 一键复制
- 在线 HTML 预览

#### 3.1.8 拼装示例（每份学生错题集）

```
┌─────────── 2026-06-20 错题集 ───────────┐
│ 学生姓名：张三                           │
│                                         │
│ 堂测错题：                               │
│ 1. 题号 T-3（图片）                     │
│ 2. 题号 T-7（图片）                     │
│                                         │
│ 作业错题：                               │
│ 3. 题号 H-12（图片）                    │
└─────────────────────────────────────┘
```

**全对学生的简化版**：
```
┌─────────── 2026-06-20 错题集 ───────────┐
│ 学生姓名：李四（今日全对）              │
└─────────────────────────────────────┘
```

#### 3.1.9 Word 模板硬约束（Apple-style 极简）⭐

**第一阶段不支持自定义模板样式**（控制开发工作量）。

**统一内置排版规范**：
- **单栏布局**（不上双栏、不上色块）
- **错题图片居中**（上下留白 8mm，左右居中）
- **题号加粗**（如 `1. T-3` 中的 `T-3` 加粗显示）
- **学生姓名大字号**（22pt + 加粗）
- **日期栏小字号 + 灰色**（12pt + #888）
- **页边距**：上 8mm / 下 14mm / 左右 10mm（与 ResumeAIX 保持一致）

**V2 再考虑**：自定义样式 / 多栏布局 / 主题色切换。

## 4. AI 提示词与文本格式规范（核心模块）

> ⭐ 助教对格式极其敏感：所有 AI 输出文本都要能直接复制到 Excel 表格列里、或者直接发到家长群里，**不能有 Markdown 符号干扰**。

### 4.1 格式级硬约束

#### 禁用 Markdown 符号
- AI 在输出多条建议时极易加上 `1.`、`2.` 或 `*`、`-`、`+`
- 这些符号直接粘到 Excel 列里会格式错乱
- **必须锁死：只换行，不加任何前缀符号**

#### 严格单行换行
- 每条建议独立成行
- 中间不能有空行
- 方便老师一键向下拖拽复制一整列

### 4.2 结构级硬约束

#### 头部动词强制 7 选 1
每条建议的第一个词必须严格从下列动词中选择开头：
```
巩固 / 加强 / 掌握 / 熟练 / 灵活运用 / 注意 / 强化
```
- 不能出现"希望、需要、同学"等大白话开头

#### 尾部鼓励语常驻
每条建议的末尾随机搭配亲切后缀：
```
继续加油！/ 再接再厉！/ 继续努力！/ 继续保持！/
多总结方法！/ 养成严谨习惯！/ 举一反三！/ 用心体会！
```

#### 条数收敛
- 助教最初设想 20-30 条
- 实际教学场景下 **10 条** 是最精简且不易重复的黄金数量

### 4.3 小结段落的"逻辑三段式 + 常驻尾注"

#### 紧凑段落不换行
- 总体小结必须是**一整个紧凑段落**，中间不换行

#### 三段式结构
段落内部必须包含：
```
解题的关键在于：第一，[具体点1]；第二，[具体点2]；第三，[具体点3]。
```

#### 固定催交话术尾注
段落末尾雷打不动加上：
```
作业未交的同学请课后及时补做，遇到疑问欢迎随时来问老师，下次记得按时交作业哦！
```

### 4.4 开箱即用的 AI Prompt 模板

> 直接配置到 ai-service 的 system 消息里，**开箱即用**。

```markdown
# Role
你是一款专为培训机构助教设计的 AI 智能授课助手（项目代号：Lekao）。你的核心任务是根据助教提供的【学科名称】和【作业内容/标准答案】，生成专业、结构化且极具亲和力的"作业反馈"与"总体小结"。

# Output Format Requirements (⚠️极其重要)
你的输出必须严格包含两个部分，且格式必须满足以下硬性约束，以便于助教直接复制粘贴到 Excel 或群发给家长：

---

本次【学科名称】作业反馈（【精准提炼的专题名称】）
【10条学习建议，格式严格遵循：指定的起始动词 + 具体能力建议 + 亲切鼓励尾语】

本次【学科名称】作业总体小结
【一整段紧凑的总结段落，包含考查重点、解题关键三段式、订正建议、以及固定催交尾注】

---

## 细节规范：

### 第一部分：作业反馈规范
1. **行数限制**：必须不多不少正好输出 10 条学习建议。
2. **禁用符号**：每条建议单独换行。严禁包含任何数字序号（如 1, 2, 3）、严禁包含任何 Markdown 列表符号（如 *, -, +）。
3. **头部约束**：每条建议的第一个字，必须严格从以下动词中选择开头：[巩固, 加强, 掌握, 熟练, 灵活运用, 注意, 强化]。
4. **尾部鼓励约束**：每条建议的句尾，必须带上一个亲切的鼓励短语，例如：[继续加油！, 再接再厉！, 继续努力！, 继续保持！, 多总结方法！, 养成严谨习惯！, 举一反三！, 用心体会！]。
5. **内容要求**：紧扣输入的作业内容，指出具体的知识点薄弱项或技巧（如：齐次化、受力分析、三段式），10条内容可以相近但绝不能完全重复。

### 第二部分：作业总体小结规范
1. **排版格式**：必须输出为**一整个紧凑的文本段落**，中间不要换行。
2. **核心内容三段式**：段落内部在阐述解题关键时，必须使用"解题的关键在于：第一，[具体点1]；第二，[具体点2]；第三，[具体点3]。"的句式结构。
3. **固定常驻尾注**：段落的最后两句话，必须雷打不动地输出以下字样（可根据学科微调语调，但意思保持一致）："作业未交的同学请课后及时补做，遇到疑问欢迎随时来问老师，下次记得按时交作业哦！"
```

### 4.5 前端联动小细节

#### 分流一键复制按钮组
- UI 上提供**两个独立的复制按钮**：
  - "复制反馈（贴 Excel 用）" → 取第一部分
  - "复制小结（发微信群用）" → 取第二部分

## 7. 技术架构

### 7.0 ⭐ 仓库策略（既定结论）：完全独立 Git 仓库

**决策**：Lekao **完全独立 Git 仓库** `TimeCraker/Lekao`，不挂在 ResumeAIX monorepo 里。

**Why**：
- 用户原话："业务上面要分开，不然到时候业务不能纠缠到一块了，会比较麻烦"
- Lekao 是独立产品，未来可能独立融资 / 独立运营 / 独立招人
- monorepo 共享依赖会带来源码耦合、版本冲突、CI 复杂度上升等问题

**可复用部分**（**不通过 Git 共享，通过设计语言共享**）：
- ✅ UI/UX 设计语言（可参考 ResumeAIX 的视觉风格、Apple-style 高对比度）
- ✅ 登录页面 UI 模式（邮箱 + 验证码 + 微信 OAuth 三件套）
- ❌ 不共享 packages/db（不复用 Prisma schema，直接独立）
- ❌ 不共享 ai-service（独立部署，独立限流）

**服务器部署路径**：未来部署到 `/home/ubuntu/Lekao/`，端口 `:3007`，与 ResumeAIX 完全隔离。

### 7.1 复用基础设施（仅运行时层面）
- **服务器**：腾讯云 111.229.200.178
- **数据库**：PostgreSQL `:5434`（**仅运行时共享 DB 连接**，但 schema 独立）
- **Redis**：`:6380`（共享）
- **AI 底座**：SiliconFlow / DeepSeek（OpenAI-compatible）
- **域名**：`lekao.asterforge.top`（待申请）

### 7.2 ⭐ Prisma 迁移防踩坑（共享 users 表的技术安全）

**背景**：Lekao 与 ResumeAIX 共享同一个 PostgreSQL 实例和 `users` 表。

**风险**：如果 Lekao 的 `prisma db push --force` 误操作，可能影响 ResumeAIX 付费用户数据。

**PRD 落地硬约束**：

1. **共享的 User 模型必须关闭 Prisma 自动迁移控制**
   - 在 Lekao 的 `schema.prisma` 中，`users` 表用 `@@map("users")` 引用但**不加任何字段**
   - Lekao 不修改 `users` 表结构，所有字段调整走 ResumeAIX 的迁移

2. **Phase 1 部署时绝对禁止 `prisma db push --force`**
   - 只允许 `prisma migrate deploy`（带历史 migration 文件的安全模式）
   - 部署脚本必须加 `--skip-generate` 和 `--accept-data-loss=false`（默认就拒绝数据丢失）

3. **Lekao 业务表独立 migrate**
   - `lekao_class_summaries` / `lekao_class_feedbacks` 等新表走 Lekao 自己的 migration
   - 与 ResumeAIX 的 migration 历史完全分离

4. **数据库 Schema 设计**：
```
-- Lekao 只读引用
users (ResumeAIX 管理，**Lekao 不修改字段**)
   ├─ id, email, password, role ...
   ├─ t_coin (充值 T-Coin，跨产品共享)
   └─ lekao_gift_coin (Lekao 赠送 T-Coin，仅 Lekao 用) ⭐ 新增字段

-- Lekao 独立表（migration 自主）
lekao_mistake_collections
lekao_class_summaries
lekao_class_feedbacks
lekao_templates
```

**重要**：`lekao_gift_coin` 字段虽然是 Lekao 用，但属于 `users` 表，必须走 ResumeAIX 的 migration 加进去（不能 Lekao 私自加，否则又触犯"共享表不动"原则）。

**执行方案**：
- 先在 ResumeAIX 仓库提一个 PR：给 `users` 加 `lekao_gift_coin Int @default(0)` 字段
- 等 ResumeAIX migration deploy 到生产后
- Lekao 才开始 migrate 自己的业务表

### 7.3 ⭐ 腾讯云 COS 前端直传方案

**问题**：服务器 3.6GB 内存紧张，AI 读图走大图片中转极易 OOM。

**方案**：
1. 后端只生成"预签名 URL（Presigned URL）"，几 KB 大小
2. 浏览器直接上传图片到对象存储
3. 应用服务器全程不接触图片大数据
4. 实现内存与带宽的"零压力"

### 7.4 ⭐ Node 进程内存硬限制
- Lekao 进程强制加上 `--max-old-space-size=512`
- 防止单服务异常拖垮整台服务器
