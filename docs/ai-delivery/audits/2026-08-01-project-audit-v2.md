# LeKao 非安全产品、内容与体验复核

## 1. 结论

当前产品“功能可构建”，但还没有形成可信、连续、可扩展的产品体验。最新仪表盘完成了局部杂志化重绘，却没有同步解决导航、任务连续性、文案真值、移动端、状态语义和质量门禁，因此不应继续逐页堆视觉效果。正确方向是先建立三类单一真值：能力与费用、任务与资产状态、设计与内容规范，再让页面消费这些真值。

本轮严格排除安全审计和安全整改。

## 4. 目标体验原则

1. **任务先于资产**：用户进入工作台先看到继续工作和新建任务，余额与签到只做辅助信息。
2. **事实先于文案**：能力、费用、平台、限制、恢复动作来自同一 registry。
3. **状态先于动画**：任何动效必须回答“发生了什么”，不能延迟信息出现。
4. **编辑台而非娱乐场**：借鉴出版物的网格、批注和纸张秩序，不复制 `ISSUE`、货币符号等无语义装饰。
5. **跨端同一任务模型**：不同设备可以呈现不同布局，但步骤、状态和用词相同。
6. **真实成功**：只有持久化、导出或结算完成才能显示成功。

## 5. 推荐顺序

1. S01：产品真值、计费补偿、真实保存、认证语义、移动导航。
2. S02：测试门禁、API 契约、Artifact 连续性、模块边界。
3. S03：内容系统、设计系统、营销站、工作台 Shell、四条流程与视觉验收。

任何 Stage 未形成独立 planning commit 前均不得派发实施。
