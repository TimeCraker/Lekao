# LeKao 产品基础与高级体验升级 PRD

## 1. 背景与问题

LeKao 已覆盖课堂小结、作业反馈、错题集、周末反馈表和灵感墙，但产品真值、跨端接口、数据保存和设计系统未形成统一契约。当前核心风险不是功能数量不足，而是用户看到的承诺与真实行为不总是一致，Web 与 Android 也没有共享可执行接口真值。

## 2. 目标用户与核心场景

- 一线助教/教师：把讲义、Excel、错题图片转为可直接交付的 Word、Excel 或群消息。
- 教培管理者：查看生成、用量和资产状态，管理账号与 T-Coin。
- 高频移动用户：在手机上完成登录、查看任务、轻量录入和结果交付。
- 跨设备用户：在 Web 与 Android 间继续同一份教学工作，而不是依赖单机缓存。

核心场景：创建工作 → 导入材料 → 校对结构化内容 → 生成/导出 → 保存和再次使用；失败时不误扣费、不伪造成功，并给出可执行恢复动作。

## 3. 目标与成功指标

1. 产品可信：所有可点击成功态均由持久化结果支撑；AI 失败后用户可用余额不减少。
2. 跨端一致：Android 声明的必需接口 100% 通过服务端 contract test；不存在“客户端有、服务端无”的核心接口。
3. 数据连续：完整 Artifact Bundle 导出后可在新浏览器恢复元数据与图片，完整性校验 100% 通过。
4. 工程可靠：`lint`、`typecheck`、单元/契约测试、build 全部成为绿色门禁；禁止以 warning/error 基线永久豁免。
5. 移动可用：320px 起登录、注册和工作台主路径无横向滚动；所有主交互触点至少 44×44px。
6. 性能：生产移动端 Lighthouse 三次中位 LCP ≤2.5s、CLS ≤0.1、TBT ≤200ms，Performance ≥90。
7. 品牌与转化：首页首屏仅一个主 CTA；新用户可在 10 秒内说清 LeKao 为谁、解决什么、输入输出和费用。
8. 任务连续：有历史的用户打开工作台后一次主点击即可继续最近工作；资产与签到不抢占任务首屏。
9. 无 Office 交付：四条流程都能在浏览器内完成「看真实成品 → 就地修改 → 交付（下载/打印/另存 PDF/批量）」，用户不需要本机 Office 或 PDF 软件。

## 4. 范围

- 产品真实性、能力矩阵、费用/阶段/错误文案。
- T-Coin 请求预留、结算、释放与幂等。
- 个人资料真实保存、条款链接、认证表单语义。
- 桌面和移动工作台导航。
- 版本化 API 契约、Android 对齐、统一 Artifact 数据模型与完整备份。
- ESLint/TypeScript/测试/CI 门禁与超大模块分层。
- “Editorial Intelligence / 教学编辑台”品牌、设计系统、营销页与工作台体验。
- LCP、客户端边界、响应式和可访问性优化。
- 最近任务、待处理恢复、能力引导和每日签到在同一工作台优先级中的正确定位。
- 浏览器内真实产物预览、就地编辑与重导出、打印/另存 PDF/批量交付。
- AI 产出直接写入教师自有 Excel（按表头识别目标列，保留原表样式）。

## 5. 非目标

- 安全风险审计与安全加固（本轮按用户要求暂停）。
- 微信支付、微信 OAuth、真实生产发布或付费资源采购。
- 未经验证的新 AI 模型或扩展全新业务线。
- 一次性重写整个仓库或同时替换 NextAuth、Prisma、Next.js。
- 在线分享链接、二维码、服务端产物归档，或任何把教学内容送出浏览器的能力（PII 边界）。
- 通用 Office 编辑器、机构自有模板的占位符引擎，以及文件级 PDF 生成引擎（PDF 走浏览器打印对话框）。

## 6. 功能需求

### FR-001 产品能力真值

系统必须维护可审计 capability registry，包含功能、平台、状态、输入、输出、费用、限制和恢复动作；营销页、帮助页与关键错误文案必须与该真值一致。

### FR-002 可靠计费

每个收费生成请求必须有唯一 idempotency key 和账务状态 `reserved | settled | released`；仅成功交付可结算，失败/超时必须释放，重复请求不得重复扣币或退款。

### FR-003 真实账户操作

用户名保存必须经服务端持久化并刷新会话；失败显示字段级或全局错误。未接入能力不得显示成功态。

### FR-004 响应式导航

桌面与移动端共享同一导航模型；移动端必须可从任一工作台页面进入四个核心功能、历史、个人中心并退出登录。

### FR-005 可执行 API 契约

服务端公开版本化 API 描述；Web route、Android 请求/响应 DTO 和 contract tests 绑定同一 schema。破坏性变更必须升级版本或提供兼容期。

### FR-006 统一教学资产

课堂小结、反馈、错题和附件必须使用稳定 Artifact ID；本地草稿、服务端记录和 Android 草稿具有明确同步状态和冲突策略。

### FR-007 完整备份与恢复

导出包必须包含 manifest、结构化数据、图片 Blob、schema version 和 checksum；导入前报告缺失/损坏项，导入后提供 added/updated/skipped/failed 准确统计。

### FR-008 高级品牌与内容系统

统一使用 LeKao 品牌名和“教学编辑台”叙事；首页按价值主张、证据、工作流、平台、费用/限制、FAQ 排列；禁止内部术语和无证据评分。

### FR-009 任务型工作台

四条工作流使用一致步骤模型：导入、校对、生成、交付；显示当前步骤、保存状态、费用影响、错误恢复和最近结果。

### FR-010 可观察的失败与恢复

核心操作必须返回 correlation id、稳定 error code、可执行恢复动作和账务状态；本地保存失败不得静默吞掉。

### FR-011 任务连续与首次引导

工作台必须优先展示“继续最近工作”和“新建教学任务”；首次使用提供真实示例输入和四步工作流说明，不能用空白页面或装饰性卡片代替下一步。

### FR-012 奖励功能不破坏核心任务

每日签到必须按 Asia/Shanghai 自然日幂等发放，七日循环规则可解释；签到、余额和活动奖励属于辅助资产区，不得排在核心任务之前，也不得暗示未开放购买能力。

### FR-013 真实产物预览

导出前必须能在浏览器内渲染真实产物（docx/xlsx 的实际字节或产前 Workbook 模型），预览与导出件由同一源模型驱动并保持一致；渲染失败必须给出非空白的摘要与重试，不得以「预览只是大致样子」之类的免责声明代替保真。

### FR-014 就地编辑与重导出

用户必须能在预览中直接修正交付物内容（学生名、题号、文字、图片增删与顺序、单元格文本）；编辑写回源模型后由既有生成器重新产出，保持「预览 = 导出 = 草稿」三方一致；批量导出必须逐份独立且不破坏本地草稿与历史。

### FR-015 无 Office 交付

交付必须支持下载（单份/批量 ZIP/目录授权）、A4 打印、浏览器另存 PDF 与批量打印队列；移动端在 File System Access 不可用时必须提供系统分享/打印或下载回退；交付失败不得产生半成品文件，且必须给出可恢复说明。

### FR-016 AI 产出落进教师自有表格

课堂小结与作业反馈的文本必须能按用户上传的目标 Excel 的表头语义写入对应行与列（识别失败允许人工指定目标列），保留原表样式；未匹配的行必须被列出而非静默丢弃。

## 7. 非功能需求

### NFR-001 质量门禁

CI 必须顺序执行 lint、typecheck、unit/contract test、build；任一失败阻断合并。禁止删除失败测试或使用永久基线忽略现有错误。

### NFR-002 性能

首屏 LCP 候选首帧可见；公开营销页不因未知会话状态阻断渲染；满足第 3 节 Lighthouse 边界。

### NFR-003 可访问性

键盘可完成全部核心路径；焦点可见；语义名称、autocomplete、错误关联完整；支持 reduced motion；触控目标至少 44×44px。

### NFR-004 一致性

计费与 Artifact 状态变化必须事务化或采用可恢复补偿；所有重试均幂等。

### NFR-005 可维护性

页面组件不直接同时承担解析、存储、网络、导出和渲染；新增/重构模块单文件建议 ≤400 行，超出必须在 Spec 中说明理由。

### NFR-006 兼容性

支持当前 Chromium/Edge/Safari；File System Access 不可用时提供下载回退；旧 history v1 只读导入并明确图片缺失限制。

### NFR-007 可观测性

收费生成、同步、导入和导出记录结构化事件，至少包含 correlation id、artifact/job id、状态、耗时和 error code，不记录原始教学内容。

### NFR-008 内容与设计治理

品牌、费用、状态、版本和能力声明不得散落硬编码；页面必须消费 capability/copy registry、build metadata 与 design tokens。新增页面必须进入路由/状态/视口验收矩阵。

### NFR-009 产物不出浏览器

讲义、图片、学生姓名与生成产物只允许在内存、IndexedDB、File System Access 与本机下载中流转；预览、编辑、打印、落表与交付都不得引入携带这些内容的网络请求或服务端存储；`references/` 样本只能以本地脱敏副本参与验证且不进 git。

### NFR-010 客户端依赖预算

`docx`、`xlsx`、`jszip`、`exceljs` 与产物渲染器只能按需动态加载，不得进入公开页或工作台首屏；新增依赖必须记录用途与体积，并在对应 Stage 记录首屏 JS 前后数字。

## 8. 验收条件

- AC-001：给 AI provider 制造可控失败后，请求返回 `released`，用户总余额与请求前相同；用同一 idempotency key 重试不会产生第二条扣款。
- AC-002：修改用户名并刷新页面及重新登录后仍显示新值；服务端失败时不显示“已保存”。
- AC-003：在 320×568 和 390×844 下，注册验证码按钮完整可见、页面无横向滚动、条款链接分别打开 `/terms` 和 `/privacy`。
- AC-004：在 390×844 的任一 dashboard 路由中，用户最多两次点击可到达任一核心功能、历史和个人中心。
- AC-005：每个 Android 必需 API 均存在于版本化契约；contract test 对状态码和响应 schema 通过；未实现能力从客户端移除或明确禁用。
- AC-006：在设备 A 导出含 3 张图片的 Artifact Bundle，在全新浏览器导入后 3 张图片 checksum 全部一致，导入统计准确。
- AC-007：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm test:contract`、`pnpm build` 全部退出 0。其中 `test:contract` 脚本由 S02 T-203 建立，`test:e2e` 由 S01 T-001 建立，`perf:audit` 由 S03 T-306 建立（见追踪矩阵完整性规则）。
- AC-008：首页、登录、注册、dashboard、四条核心工作流在 320/390/768/1440 宽度没有非预期横向滚动；主交互触点 ≥44×44px。
- AC-009：生产移动端 Lighthouse 连续三次中位 Performance ≥90、LCP ≤2.5s、CLS ≤0.1、TBT ≤200ms。
- AC-010：首页主 CTA 唯一且为“免费创建工作台”；页面不出现“BRD”等内部术语、无证据评分或未开放充值的不可执行指令。
- AC-011：关闭/限制 IndexedDB 或 localStorage 后，保存操作显示可恢复错误，不出现“已保存”；恢复存储后重试成功。
- AC-012：所有核心失败响应包含稳定 error code、correlation id、recovery action 和适用的 billing state。
- AC-013：有最近任务时，dashboard 首屏第一主动作是“继续上次工作”；无最近任务时第一主动作是“新建教学任务”；余额和签到位于任务区之后。
- AC-014：公开站、认证、dashboard 和四条流程只使用登记的核心 token；不存在手写版本号、伪 `ISSUE`、无业务含义 `¥` 水印或公开 `Lekao Agent`。
- AC-015：同一用户同一自然日重复签到只产生一次奖励；第 7 天后正确回到第 1 天；0 点边界以 Asia/Shanghai 计算。
- AC-016：浏览器预览的错题集 docx 与导出件在文本、图片数量与顺序、分页上一致；周末表预览的合并单元格/列宽/样式与导出件一致；差异清单为空或已逐条记录。
- AC-017：在预览中修改学生姓名、题号文本或图片后重新导出，导出件与预览一致，且 localStorage 草稿、IndexedDB 图片与 history.json 未被破坏。
- AC-018：周末反馈表在导出前可确认真实表样（多 Sheet），单元格修正后导出仍保留原模板的 merges/cols/styles。
- AC-019：AI 小结/反馈写入教师上传的反馈表后落在正确行与列，未匹配行被列出；导出文件保留原表 merges/styles/cols，无需复制粘贴到 Office。
- AC-020：错题集与周末表可 A4 打印且无横向溢出、页码与页眉正确；390×844 视口下下载/打印/分享回退可用；交付全过程的网络请求不携带产物内容。

## 9. 约束、已定决策、风险与依赖

### 已定决策

- 不做大爆炸重写；阶段顺序修订为 S01 → S04（无 Office 交付）→ S03（品牌与体验）→ S02（跨端对齐）：S04 是纯客户端产物层，先落地可避免 S03 重做四条流程视图；S02 放到最后，让 Web 契约冻结一次即被 Android 消费。
- 产物不出浏览器是本轮硬边界：预览、编辑、打印与落表全部在客户端完成，不新增服务端存储或分享通道。
- 交付保真的判定方式是「同一源模型驱动的预览与导出件一致」，不是渲染器自称支持某种格式。
- 设计方向为 Editorial Intelligence / 教学编辑台，拒绝泛用玻璃拟态与无意义 AI 渐变。
- LCP 内容不做延迟透明入场；动效只能增强，不能成为内容可见前提。
- capability registry、API schema 和 design tokens 分别成为内容、接口和视觉的单一真值。
- “高级”定义为任务层级清晰、状态可信、排版精确和动效克制，不以 3D tilt、磁吸、鼠标尾迹或装饰性英文命名作为验收依据。

### 风险与依赖

- 共享 `users` 表归属可能涉及 ResumeAIX 仓库，任何迁移需明确 owner。
- Android 真机、邮件、AI provider 和生产数据库属于外部证据，缺失时相应 AC 保持 BLOCKED。
- 旧本地历史缺少图片 Blob，无法无损补回；迁移只能明确降级。
- 本轮不开放支付，因此所有充值文案必须按当前能力收敛。
- S04 依赖 `docx-preview` 对本仓 `docx` 9.x 生成件的保真度；若实测不足，只能如实降级并记录差异，不得以免责文案掩盖。
- S02 后置使 S03/S04 的交付步只能展示本地保存状态；统一 Artifact 状态的接入由 S02 承接，S03/S04 不得自行发明服务端状态。
- S03 的 AC-008/009/013 与 a11y 门禁依赖 `pnpm test:e2e`（S01 T-001 建立）与 `pnpm perf:audit`（S03 T-306 建立）；这两个脚本当前不存在，在前置任务落地前相关 AC 只能保持未验证。
