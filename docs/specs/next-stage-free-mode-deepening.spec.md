### 1.2 余额经济学测算（由 1.1 规则推算）

- 满勤签到周收入 = 2+3+4+5+6+7+8 = **35 币/周 ≈ 5 币/天**，月收入 ≈ 150 币。
- 典型助教日耗（工作日小结 1 + 反馈 1）= 2 币/天，周耗 ≈ 10–14 币；即使加上周末反馈表（1 币/Sheet，通常 1–3 Sheet），月耗 ≈ 50–70 币。
- **结论：获取 ≫ 消耗，余额单调上涨，无回收出口（sink）**。三个后果：
  1. 余额高企后签到失去感知价值，留存钩子钝化；
  2. 囤币 = 未来真实 AI 调用成本的无限承诺（每币对应一次 Qwen3-VL + DeepSeek 真实调用，免费模式下 T-Coin 的角色是**节流阀 + 留存钩子**，不是收入）；
  3. 缺少「花币买高价值能力」的场景，币在系统里只出不进的另一端也空转。
- 反面约束：上限不能压到影响正常使用——目标用户是机构助教，日用 2–3 次生成是健康频率，护栏必须高于这条线。

## 2. 目标与非目标

### 2.1 目标

1. **G1 T-Coin 获取体系**：从「只有签到」扩展为「签到 + 每日任务 + 一次性成就」三个获取途径，全部幂等、可审计、有日获取上限。
2. **G2 T-Coin 消耗场景**：为 2–3 个新 AI 能力设计分级定价，让币有高价值去处；基础能力维持 1 币不变。
3. **G3 余额经济学护栏**：赠送池封顶防囤币通胀；任务 / 成就判定只认真实成功生成，防刷；不做余额过期（建议，待拍板）。
4. **G4 助教能力升级**：新增 2–3 个以「机构教师省时间」为北极星的 AI 能力（候选：学情周报、错题归因、作业批改辅助），复用既有计费 / 流水线 / 交付面板，不另起炉灶。
5. **G5 真值一致**：所有新能力与经济参数进 capability registry 与集中配置，文案一致性测试同步扩展（延续 S01 FR-001 纪律）。

### 2.2 非目标

- ❌ 任何付费 / 充值 / 变现方向（买币、订阅、增值包、广告）——红线。
- ❌ T-Coin 转账、赠送、交易、排行榜竞价等用户间流通（防刷复杂度不成比例）。
- ❌ 重构现有三项能力的计费模式（已由 S01 状态机收敛，本阶段只**新增**消费场景）。
- ❌ Android 端适配（S02 已 CANCELLED，web-only 决策不变；新能力默认 web-only）。
- ❌ 改动 AI 双阶段流水线架构（Qwen3-VL + DeepSeek）、更换模型供应商。
- ❌ 灵感墙奖励化（灵感墙是社区功能，发币会诱导灌水；如要做单独评审）。
- ❌ 服务端存储学生粒度数据（NFR-009 产物不出浏览器边界不变；云端只存已落盘的生成文本）。

## 3. 用户故事

**T-Coin 获取**

- US-01 作为助教，我每天签到之外还能通过「完成 1 次成功生成」这类小任务多拿 1–2 币，让我感到日常使用被持续奖励，而不是只有打开控制台那一秒有价值。
- US-02 作为重度用户，我累计生成 50 次时解锁一次性成就奖励，产品认可我的持续使用；这个成就只能领一次，我无法通过删除重来的方式反复领。

**T-Coin 消耗与余额**

- US-03 作为攒了一堆币的助教，我愿意花 2 币生成一份「本周班级学情周报」，因为周末要向教务 / 家长汇报，这比我自己翻一周记录拼总结快得多。
- US-04 作为助教，我能在一个页面看清「币从哪来、到哪去」（签到 / 任务 / 成就 / 每次生成扣费），不再觉得余额是笔糊涂账。
- US-05 作为接近余额上限的助教，系统明确告诉我「赠送币已达上限，继续签到可保持连续记录但不再入账」，规则可解释（延续 FR-012「七日循环规则可解释」精神）。

**助教能力**

- US-06 作为班主任，周五我选「本周」，Lekao 把我这周的小结 / 反馈聚合成一份班级学情周报（表现摘要、进步点、关注点、家庭配合建议），我校对后直接发教务群。
- US-07 作为助教，我上传周末反馈表后花 1 币得到「错题归因」：每个学生错在概念不清还是审题粗心，附举一反三练习建议——错题集从「记录」升级为「解释」。
- US-08（若批改辅助入选）作为助教，我拍学生作业照片，AI 逐题标出对 / 错 / 半对并给订正要求草稿，我终审后用——AI 是辅助，判分责任在我。

## 4. 功能需求（FR，按能力分组编号）

> 编号规则：FR-`<组>` `<序号>`，组 A = 获取体系、B = 消耗与定价、C = 经济学护栏、D = 新能力。数值均为建议默认值，最终以 §9 拍板为准。

### 4A. T-Coin 获取体系

- **FR-A1 奖励发放账本**：所有非 admin 的币发放（签到 / 任务 / 成就）统一走与扣费同级的幂等账本：`award ledger`（建议新表 `lekao_award_ledger`，`(userId, awardKey)` 唯一，`awardKey` 如 `checkin:2026-10-05` / `task:daily-gen:2026-10-05` / `achieve:first-generation`），并同步写 `lekao_coin_log`。重放 / 并发不超发。
- **FR-A2 每日任务**：任务池固定且小（首发建议仅 1 项：「当日完成 ≥1 次**成功结算**的 AI 生成」→ +1 币）。任务完成状态当日有效，次日重置；判定数据源 = `lekao_generation_charges` 中 `state='settled'` 的当日记录（天然防「故意失败刷任务」，失败生成不结算）。
- **FR-A3 一次性成就**：里程碑成就表（建议首发：首次成功生成 +3 · 累计 10 次 +5 · 累计 50 次 +10 · 累计 100 次 +20 · 连续签满 4 周 +10），DB 唯一约束保证只发一次；成就进度对用户可见（「50 次：还差 12 次」）。
- **FR-A4 获取总览**：控制台「资产区」展示三个途径的今日状态（已签 / 任务进行中或已完成 / 下一个成就进度），**延续 FR-012：资产区排在核心任务之后，不抢占首屏**。

### 4B. T-Coin 消耗与定价

- **FR-B1 分级定价表**：新增能力的定价集中登记（capability registry 为真值），建议：学情周报 2 币/份 · 错题归因 1 币/次 · 批改辅助 2 币/次（若入选）。现有三能力 1 币定价不变。
- **FR-B2 计费复用状态机**：新能力扣费一律走 `reserveCoin / settleCoin / releaseCoin`（operation 枚举扩展），成功才结算、失败自动释放，幂等键规则与现有一致。
- **FR-B3 余额明细页**：按时间倒序展示获取 / 消耗流水（签到 / 任务 / 成就 / 各能力扣费 / 释放返还），复用 `lekao_coin_log` + award ledger 数据；只看本人。

### 4C. 余额经济学护栏

- **FR-C1 日获取上限**：签到 + 任务 + 成就合并计入日获取上限（建议 10 币/日；成就属一次性，建议不计入日上限、单独计量）。达到上限后当日不再入账，UI 明示规则。
- **FR-C2 赠送池封顶**：`lekao_gift_coin` 余额上限（建议 200 币）。达到上限后：签到仍可签（连续记录不断）、streak 照常推进，但奖励币不入账并提示原因；消耗后低于上限自动恢复入账。admin 调币不受上限约束（补偿通道）。
- **FR-C3 无过期策略（建议）**：赠送币不过期、不定期清零。理由：过期对留存的伤害（「我的币被没收了」）大于防通胀收益，封顶已控制敞口；K12 用户有寒暑假周期，学期中断不应惩罚。**此条为建议，待所有者拍板**（§9-Q3）。
- **FR-C4 t_coin 池处理（开放）**：免费模式下 `t_coin` 已无获取渠道，展示层建议合并为单一「T-Coin 余额」+ 明细标注来源池；数据层是否冻结 / 收敛涉及 ResumeAIX 共享表，**只做展示层收敛，不动数据层**（除非所有者另行决策，§9-Q4）。

### 4D. 助教能力升级（建议首批 D1 + D2，D3 二期——§9-Q5）

- **FR-D1 学情周报（weekly-report）**：
  - 输入：时间范围（本周 / 近 7 天 / 自定义 ≤30 天）+ 可选补充描述；班级模式数据源 = 本人云端历史（`lekao_class_summaries` + `lekao_class_feedbacks`，userId 隔离）；学生模式数据源 = 用户本地上传的周末反馈表 Excel（客户端读取，不落库，NFR 边界不变）。
  - 处理：聚合统计 → DeepSeek 生成（**无需 vision**，纯文本管线，成本低、延迟小）。
  - 输出：班级周报（各科表现摘要 / 进步点 / 关注点 / 家庭配合建议）或按学生周报；可复制、走统一交付面板（S04）导出 / 打印。
  - 计费：2 币/份；历史记录落盘（沿用付费数据落盘防客诉原则，新表或扩展现有表待任务设计）。
- **FR-D2 错题归因（mistake-attribution）**：
  - 输入：周末反馈表 Excel（学生 × 题目对错记录，客户端解析，复用 `weekend-headers.ts` 表头识别）。
  - 处理：错题统计 → DeepSeek 按错误类型归因（概念不清 / 审题失误 / 计算粗心 / 方法未掌握 四类固定枚举，prompt-injection 清洗沿用 allowlist 模式）+ 举一反三练习建议。
  - 输出：按学生或按题的归因报告，可独立导出或作为周报「关注点」素材并入 FR-D1。
  - 计费：1 币/次；纯文本管线。
- **FR-D3 作业智能批改辅助（grading-assist，二期候选）**：
  - 输入：学生作业 / 试卷照片 ≤5 张 + 可选标准答案 / 讲义图片。
  - 处理：Qwen3-VL 识别手写作答 → 逐题判「对 / 错 / 半对」三态 → DeepSeek 生成订正要求草稿。
  - 输出：逐题批改清单 + 正确率与薄弱题号汇总；**界面强制标注「AI 辅助草稿，判分以教师终审为准」**。
  - 计费：2 币/次（vision 双阶段成本高于纯文本）。
  - 风险与红线：判分准确性不做承诺、家长端交付需教师终审；学生手写 PII 提示遮挡姓名（讲义图片已走 AI provider 属同类边界，但手写作答个人属性更强，UI 需显式提示）。

### 4E. 真值与文案（贯穿）

- **FR-E1 registry 扩展**：每个新能力上线时同步登记 `src/config/capabilities.ts`（inputs / outputs / billing / limits / recovery 全字段）+ `capability-copy.test.ts` 文案一致性断言；经济参数（日上限 / 封顶 / 定价 / 奖励表）集中到一个配置模块，不散写。

## 5. 非功能需求（NFR）

> 沿用 PRD v3 既有 NFR 编号者不重复展开；新约束用 NFR-N 前缀。

- **NFR-004（沿用）幂等与事务**：奖励发放与扣费同级幂等；所有重试不重复入账 / 扣币。
- **NFR-007（沿用）可观测**：奖励发放、新能力生成记录结构化事件（correlationId / awardKey / 状态 / 耗时 / error code），不记录教学内容原文与学生姓名。
- **NFR-009（沿用）产物不出浏览器**：学生模式周报与错题归因的本地 Excel 数据只在客户端解析；上传给 AI 的内容仅限生成所需的最小文本片段，不整表上传，不落库。
- **NFR-N1 经济参数集中配置**：定价、上限、封顶、奖励表全部收敛到单一配置模块 + 单元测试锁定，调整参数不改业务代码。
- **NFR-N2 防刷下限**：任务 / 成就判定数据源必须是服务端已结算账本（settled charges），不得依赖客户端上报「我完成了」。
- **NFR-N3 首屏预算不回退**：新能力入口与资产区 UI 不引入重依赖；延续 NFR-010 按需加载纪律，各任务记录首屏 JS 前后数字。
- **NFR-N4 建议先埋点后调参**：本阶段第一个任务交付经济数据看板（admin：获取 / 消耗分布、余额分布、任务完成率），后续参数调整以数据为依据，不拍脑袋改。

## 7. 任务分解草案（带依赖序）

> 粒度为工作包（W），正式 Tasks 文件在评审通过后拆分；依赖用 ← 表示。标注估时供排期参考（人日，单人）。

```
W1 奖励发放账本 + 经济参数配置模块（FR-A1/NFR-N1，含单测）          2d
W2 余额明细页 + 控制台资产区改版（FR-A4/FR-B3）            ← W1     2d
W3 每日任务引擎（FR-A2 + AC-A3 判定链路）                  ← W1     2d
W4 一次性成就引擎（FR-A3：表/判定/进度 UI）                ← W1     3d
W5 余额封顶 + 日获取上限（FR-C1/C2，含并发测试）            ← W1     2d
W6 admin 经济看板（NFR-N4：获取/消耗/余额分布）             ← W1     1.5d
W7 学情周报·后端（FR-D1 聚合 + prompt + 计费 + 落盘）        ← W1     3d
W8 学情周报·前端（工作台入口 + 交付面板复用 + 学生模式表格读取）← W7   2.5d
W9 错题归因（FR-D2 全栈，复用 W8 的表格读取入口）            ← W8     2.5d

W12 e2e 扩展 + 全量回归 + 真实页面走查（AC-E3）              ← 全部   2d
```

关键路径：W1 → W3/W5 → W7 → W8 → W9 → W12，合计约 **15–17 人日**（不含 W10）。
建议切分为两个正式 Stage：**Stage A「T-Coin 经济体系」**（W1–W6 + W11）与 **Stage B「学情周报 + 错题归因」**（W7–W9 + W12），各自独立验收；W10 视 §9-Q5 决策单独立项。

## 9. 开放问题（留给所有者决策）

> 以下每项给出我的建议，最终由所有者拍板；拍板结果回填本节后本草案升级为正式 Stage 包。

- **Q1 新能力定价表**：建议 周报 2 币/份 · 归因 1 币/次 · 批改 2 币/次。备选：全部 1 币（简单但无分级）；周报 3 币（高价值锚点）。
- **Q2 日获取上限与封顶值**：建议 日上限 10 币（签到满额 8 + 任务 1–2）、赠送池封顶 200 币（≈ 满勤 6 周签到量，覆盖重度月耗仍有余）。数值敏感，建议看板数据支撑后微调。
- **Q3 过期 / 清零策略**：建议**不做**（FR-C3 理由）。若所有者倾向做过期，需定义学期周期边界与提前提醒机制，复杂度 +3 人日。
- **Q4 t_coin 数据层收敛**：本阶段只做展示收敛。是否彻底冻结 / 归零 `t_coin` 涉及 ResumeAIX 共享表所有权，若要做需单独立项并与 ResumeAIX 仓库协调。
- **Q5 能力优先级与 D3 取舍**：建议首批 D1 周报 + D2 归因（复用既有管线与数据，风险低、离「省时间」最近）；D3 批改辅助二期单独评审（R4 信任风险 + vision 成本）。
- **Q6 成就奖励数值表**：建议首发 5 项（FR-A3 列表）。是否加「邀请成就」？（邀请码体系已存在但发放已停，恢复邀请奖励需评估渠道）。
- **Q7 Stage 切分确认**：按 §7 建议切 Stage A（经济体系）/ Stage B（周报 + 归因）两个正式 Stage，还是合并为一个大 Stage？建议前者（独立验收、风险隔离）。
- **Q8 上线节奏**：经济体系（改存量行为：封顶 / 明细）与新增能力是否分两次部署？建议分两次，第一次部署后观察一周看板数据再上能力。
