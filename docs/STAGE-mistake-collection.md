## 1. 用户新增决策（PRD 未写 · 2026-06-20 敲定）

### 1.1 本地文件夹方案 ⭐

| 项            | 决策                                                       | 理由                                                                        |
| ------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| **技术选型**  | **File System Access API**（Chrome/Edge 原生）             | 用户每天都有新表格，老款"每次下载 docx"模式跨天丢失历史；本地方案能跨天累积 |
| **触发时机**  | 用户首次进入错题集页面时，提示"授权文件夹"                 | 不能强制首次阻塞，但要在 UI 上明确告知                                      |
| **目录结构**  | `{授权文件夹}/{学科}/{学生姓名}.docx`                      | 按学科分文件夹，方便分类管理                                                |
| **跨浏览器**  | Safari/Firefox 显示提示"请使用 Chrome/Edge"                | 不能假设兼容性                                                              |
| **权限记忆**  | IndexedDB 存 FileSystemDirectoryHandle                     | 浏览器自动续期权限                                                          |
| **增量追加**  | 检测同名 docx → 读取 → 追加新一天 section → 写回           | 不是覆盖，是累积                                                            |
| **存量 docx** | 已有的 docx 不解析（保持只追加模式），避免破坏用户手工编辑 | 简单可靠                                                                    |

**为什么不做 Electron/Tauri 桌面打包**：会增加打包复杂度、代码签名、自动更新等额外负担，Web + File System Access API 已能满足核心需求。

### 1.2 Word 输出：累积 docx 模式 ⭐

| 项                                     | 决策                                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| **一份 Word = 一位学生**（按学科独立） | 跨天累积在同一个 docx                                               |
| **每天 = 一个 section**                | 大标题写日期，下方列当天错题                                        |
| **示例**                               | `学生甲-化学.docx` 包含 6/14、6/21、6/28 三天错题（按时间正序追加） |

**为什么不做"每天独立 docx"**：用户原话"一打开 Word 就能看到该学生所有错题历史，查阅方便"。

### 1.3 错题号去重粒度 ⭐

| 项                 | 决策             | 例                                                    |
| ------------------ | ---------------- | ----------------------------------------------------- |
| **大题粒度**       | 不拆括号内小题号 | `1（2 8）2（7）` → 去重 `["1", "2"]`，不拆 `2, 7, 8`  |
| **保留原样字符串** | 不规范化         | `针2` 原样保留为 `"针2"`                              |
| **状态词过滤**     | ❌ 不过滤，全留  | `"全对"`、`"未交"`、`"上节课请假"` 都作为"题号"进槽位 |

**为什么不拆小题**：用户原话"如果分小题的话，它前面没有大题的题干，还是不能做这个错题本"——大题是完整错题截图单位。

### 1.4 堂测 / 作业 分开

| 项                      | 决策                                     |
| ----------------------- | ---------------------------------------- |
| **两个独立池子**        | 堂测一组、作业一组，分别去重             |
| **Word 分两个 section** | 【堂测错题】+ 【作业错题】，用户一眼区分 |
| **统计独立**            | 各自显示"X人错"计数                      |

**为什么不合并**：作业题和堂测题是不同试卷，混一起会让错题集逻辑混乱。

### 1.5 题号槽位：图片 + 文字并存

| 项           | 决策                                             |
| ------------ | ------------------------------------------------ |
| **必填字段** | 姓名 + 错题号                                    |
| **可选字段** | 图片 **和/或** 文字描述                          |
| **全对处理** | "全对"作为特殊题号槽，文本固定为"全对"，可加评语 |
| **三种状态** | (a) 仅图片 (b) 仅文字 (c) 图片 + 文字            |

**为什么灵活**：用户原话"也可以不粘图片，就是单纯的一个文字型的题目，也可以直接去输入进去"。

### 1.6 Sheet 处理粒度

| 项                 | 决策                                                                |
| ------------------ | ------------------------------------------------------------------- |
| **一次一个 Sheet** | 用户上传 Excel → UI 列出所有 Sheet → 用户点选 1 个 → 只处理该 Sheet |
| **UI 引导**        | Sheet 列表带 Sheet 名预览 + 前 3 行数据预览                         |

**为什么不做"一键处理全部"**：不同学科错题不同，混在一起生成会让文件管理混乱。助教一次专心处理一个学科更可控。

### 1.7 跨 Sheet 姓名

| 项                     | 决策                                      |
| ---------------------- | ----------------------------------------- |
| **每个学科独立文件夹** | `桌面/错题集/化学/`、`桌面/错题集/物理/`  |
| **同名学生不合并**     | 化学的学生甲、物理的学生甲是两个独立 docx |

## 2. 端到端数据流

```
┌─────────────────────────────────────────────────────────────┐
│ Step 1 · 用户上传 Excel (.xlsx / .xls / GBK 兼容)          │
│        → SheetJS 解析                                       │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 2 · UI 列出所有 Sheet + 前 3 行预览                     │
│        → 用户点选 1 个 Sheet（学科）                          │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 3 · 解析 Sheet                                         │
│   - 模糊识别列：姓名 / 堂测错题 / 作业错题                     │
│   - 提取每行学生 → { 姓名, 堂测QNumbers, 作业QNumbers }      │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 4 · 错题号去重 + 排序                                   │
│   - 堂测组: 全班去重 → ["1", "2", "7", "针2"]               │
│   - 作业组: 全班去重 → ["1（2 8）", "3"]                     │
│   - 按"数字优先"排序（1, 2, 7, 10 → 不是字母序）             │
│   - 统计每题错的人数                                        │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 5 · UI 渲染                                            │
│   左：堂测错题号列表 + 作业错题号列表（带"X人错"）            │
│   右：每个题号槽位（点击上传 / Ctrl+V 粘贴 / 文字输入）      │
│   → 存 LocalStorage（轻数据）+ IndexedDB（图片 Blob）        │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 6 · 用户点"导出"                                       │
│   - 检查是否已授权本地文件夹（File System Access API）       │
│   - 未授权 → 弹授权提示                                     │
│   - 已授权 → 路径: {folder}/{学科}/{学生姓名}.docx           │
└────────────────────────┬────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 7 · Word 生成（docx 库）                                │
│   - 增量模式：检测同名 docx 存在 → 读出 → 追加当天 section   │
│   - 全量模式：无 docx → 新建完整模板                         │
│   - 写回本地文件夹                                          │
└─────────────────────────────────────────────────────────────┘
```

## 5. 数据结构

```typescript
// lib/mistake/types.ts

// 单个学生在一节课的错题信息
export interface StudentMistakes {
  rowIndex: number; // 在 Sheet 中的行号（用于追溯）
  name: string; // 姓名（必填）
  classroomQNumbers: string[]; // 堂测错题号（"1", "2", "针2", "全对"）
  homeworkQNumbers: string[]; // 作业错题号
  isAllCorrect: boolean; // 是否全对（两列都"全对"或空）
}

// 整个 Sheet 的解析结果
export interface MistakeCollection {
  sheetName: string; // "化学冲刺班"
  classroomName: string; // 从 Sheet 第 1 行抓的班级名
  date: string; // 从 Sheet 第 1 行抓的日期（ISO 格式）
  students: StudentMistakes[];
  rawSheetData: unknown[][]; // 原始 Sheet 数据（用于预览）
}

// 去重后的题号（含计数）
export interface DedupedQNumber {
  qNumber: string; // "1" / "2" / "针2" / "1（2 8）"
  errorCount: number; // 错的人数
  isAllCorrect: boolean; // 是否所有错这个题的人都标了"全对"
}

// 单个题号槽位的用户填写内容
export interface QNumberSlot {
  qNumber: string; // 对应的题号
  qType: "classroom" | "homework";
  imageBlob?: Blob; // 上传的图片（IndexedDB 存）
  textContent?: string; // 文字描述
  isMarkedAllCorrect: boolean; // 手动标记全对
}

// 单个学生的完整 Word 数据
export interface StudentWordData {
  studentName: string;
  sheetName: string; // 学科
  date: string; // ISO 日期
  classroomSlots: QNumberSlot[];
  homeworkSlots: QNumberSlot[];
}
```

## 7. Word 模板规范

### 7.1 文件命名

`{学生姓名}.docx`（学科通过文件夹名区分，不在文件名里）

### 7.2 文档结构（累积模式）

```
┌──────────────────────────────────────────────────┐
│  顶部 · 摘要（首次新建时生成，永不更新）           │
│  ─────────────────────                          │
│  姓名：学生乙                                    │
│  学科：化学                                      │
│  错题汇总：累计 N 天 · M 道错题                  │
│  创建日期：2026-06-14                            │
├──────────────────────────────────────────────────┤
│                                                  │
│  ─── 2026-06-14（第 1 次）───                  │
│                                                  │
│  【堂测错题】                                    │
│  1. 题号 1                                       │
│     [图片 / 文字]                                │
│  2. 题号 2                                       │
│     [图片 / 文字]                                │
│                                                  │
│  【作业错题】                                    │
│  1. 题号 1（2 8）                                │
│     [图片 / 文字]                                │
│  2. 题号 针2                                     │
│     [图片 / 文字]                                │
│                                                  │
│  ─── 2026-06-21（第 2 次）───                  │
│  ...（同上结构）                                  │
│                                                  │
└──────────────────────────────────────────────────┘
```

### 7.3 Apple-style 排版（PRD §3.1.9）

| 项       | 值                           |
| -------- | ---------------------------- |
| 单栏布局 | ✅                           |
| 错题图片 | 居中，上下留白 8mm，左右居中 |
| 题号加粗 | ✅（如 "1. **1**"）          |
| 学生姓名 | 22pt + 加粗（顶部摘要）      |
| 日期     | 16pt + 加粗（每天段标题）    |
| 页边距   | 上 8mm / 下 14mm / 左右 10mm |

### 7.4 docx 库选择

使用 `docx` npm 包（[docx.js](https://docx.js.org/)）：

- 纯前端生成（不需要后端）
- 支持图片插入（PngImage / JpegImage）
- 支持富文本段落、表格、分节符
- 体积约 1MB（gzip 后约 300KB）

## 9. 反模式 / 陷阱

### 9.1 不要拆分大题内的小题号 ❌

```
❌ "1（2 8）" 拆成 ["1-2", "1-8"] 当两个题号
✅ "1（2 8）" 作为一个完整题号处理（截图单位 = 大题）
```

**Why**：用户原话"如果分小题的话，它前面没有大题的题干，还是不能做这个错题本"。

### 9.2 不要规范化"针2" ❌

```
❌ "针2" 规范化为 "2"
✅ "针2" 原样保留为 "针2"
```

**Why**：用户原话"原样全留"，"针"可能是讲义代号，丢失就丢了信息。

### 9.3 不要把堂测 + 作业合并去重 ❌

```
❌ 所有错题号放一个池子去重
✅ 堂测一组、作业一组，Word 两个 section
```

**Why**：堂测和作业是不同试卷，混一起学生/家长看不出是哪种。

### 9.4 不要每下载一次就生成新 docx ❌

```
❌ 每次导出都生成 "学生甲-化学-0614.docx" "学生甲-化学-0621.docx"
✅ 累积追加到 "学生甲-化学.docx"，按日期分 section
```

**Why**：用户原话"一打开 Word 就能看到该学生所有错题历史"。

### 9.5 不要在本地文件夹里再建一层学生文件夹 ❌

```
❌ 桌面/错题集/化学/学生乙/学生乙.docx
✅ 桌面/错题集/化学/学生乙.docx
```

**Why**：学科已经分文件夹，再按学生分文件夹会增加不必要的嵌套深度。

### 9.6 不要把图片转 base64 塞 docx ❌

```
❌ 把图片转 base64 字符串塞进 Word XML（docx 会膨胀到几 MB）
✅ 用 docx 库的 ImageRun（PngImage / JpegImage），自动管理图片资源
```

**Why**：base64 编码会让 docx 文件膨胀 1.3 倍，而且 Word 打开慢。

### 9.7 不要在解析时强依赖标准模板 ❌

```
❌ 列名必须是"姓名/堂测错题/作业错题/备注"才解析
✅ 列名模糊识别：姓名/名字/Name/学生姓名 都行；堂测/课堂测验/Quiz 都行
```

**Why**：用户真实业务表有 5+ 种列名变体，强匹配会漏掉大部分。

### 9.8 不要在 Safari/Firefox 上静默失败 ❌

```
❌ 用户用 Safari 访问错题集页面，授权按钮点了没反应
✅ 检测 API 支持，不支持时显示"请使用 Chrome/Edge"提示
```

**Why**：File System Access API 是 Chrome/Edge 原生，Safari/Firefox 不支持。
